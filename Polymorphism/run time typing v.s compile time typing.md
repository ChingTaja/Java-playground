1. **compile time type** 可以想像成是 宣告型別 (Declared Type)

- 這是編譯器在檢查程式碼正確性時所參考的型別
- 它決定了你開發時能呼叫哪些方法

2. LVTI 的本質：只是「語法糖」

- **並非動態型別**：`var` 絕對不是讓 Java 變成像 JavaScript 那樣的動態型別語言
- **底層不變**：不論你寫 `Movie m = ...` 還是 `var m = ...`，編譯器產生的 `class` 檔案（位元碼）是一模一樣的
- **自動填空**：`var` 只是讓編譯器幫你把本來要寫的型別名稱「填上去」而已

3. 執行時期型別 (Runtime Type)

- 這才是物件在記憶體中真正的型別（機器本體）
- 多型（Polymorphism）就是在執行時期根據這個真實型別來決定具體行為


1. 編譯時型別 (Compile Time Type) = 「合約」

- **定義**：你在程式碼中寫下的型別（或是 `var` 推斷出來的型別）。
- **角色**：它是編譯器的檢查依據，決定了你**「現在能呼叫哪些方法」

2. 執行時型別 (Runtime Type) = 「本體」

- **定義**：程式執行時，記憶體中實際產生的物件型別。
- **角色**：決定了方法被呼叫時**「具體會執行哪段程式碼」**。

3. 繼承賦值規則 (Inheritance Rule)

- **向上轉型 (Upcasting)**：子類別物件永遠可以放進父類別變數中(可以將一個實體指派給相同型別、父型別或祖先型別（包括最終基類 java.lang.Object）的變數)
- **終點**：所有類別最終都能放進 `Object` 型別變數中。

4. 為什麼需要這種差異？

- **多型的精髓**：如果編譯時與執行時型別必須完全一樣，我們就得為每一種電影（Adventure, Comedy...）寫一套重複的邏輯 
=> 雖然使用了單一的編譯時型別 Movie，實際上卻支援了四種不同的執行時型別
- **彈性**：有了差異，我們只需寫 `Movie.watchMovie()`，Java 就會在執行時自動幫我們跑出正確電影類型的劇情。
