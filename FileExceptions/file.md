# 與 **操作系統（OS）的真實環境** 進行深對話

**理解外部資源、操作系統底層如何開啟檔案、正視例外處理（Exception Handling）與自動關閉資源（AutoCloseable）
並釐清 Java 歷史上三大 I/O 家族（IO、NIO、NIO.2）的進化史

### 什麼是外部資源（Resources）？

在 JVM 之外的世界，資源指的是所有不屬於 Java 記憶體管理的外部實體：

- 檔案系統
    
- 網路連線 與通訊端（Sockets）
    
- 資料庫連線
    
- 各種輸入/輸出串流
    

在 Java 中，建立一個檔案物件看起來就像一般的 `new Object()` 一樣簡單，你不需要手動呼叫 `open()`，這很容易讓人**忘記你其實已經向操作系統借用了珍貴的資源**

### 當你在 Java 開啟檔案時，操作系統底層發生了什麼事？

當你實例化 Java 的檔案存取類別時，Java 會把工作委託給作業系統（OS），由作業系統在它的檔案系統中執行以下一連串複雜的底層防禦與管理動作：

1. 檔案存在性檢查：確認該檔案是否真的存在於硬碟上
    
2. 權限稽核（Permissions Check）：檢查當前的執行程序（Process）或使用者，有沒有權限進行你要求的存取（唯讀、寫入或執行）
    
3. 元資料讀取（Metadata）：獲取檔案的大小、創建時間、擁有者等基本屬性
    
4. 配置檔案描述符（File Descriptor / Handle）：作業系統會分配一個數字代號（Handle）作為這包檔案的「把手」，並在 OS 內部的「開啟檔案控制表」中登記一筆紀錄
    
5. 檔案鎖定（File Locking）：根據需求決定是否鎖定檔案，防止其他軟體同時修改造成檔案損毀
    
6. 緩衝區配置（OS Buffering）：在操作系統層面分配記憶體快取，優化後續的讀寫效率
    

> 為什麼一定要關閉檔案？ 
作業系統配置的「檔案描述符（File Descriptor）」和「緩衝記憶體」是有限的
如果你一直開著不還（維持 Open 狀態），記憶體就會被吃光，其他程式甚至連你自己的程式接下來都無法再開啟任何檔案！

幸好現代 Java 大部分的資源類別都實作了 `AutoCloseable` 介面
讓我們可以透過 `try-with-resources` 自動釋放資源
這也是接下來要重頭戲講解的例外處理核心

###   I/O 三大巨頭

Java 的輸入輸出 API 經歷了三十年的演進，有三個經常在 legacy 舊程式碼與現代專案中交織出現的名詞：

#### 1. 始祖：IO (`java.io`) — 傳統阻塞式 I/O

- **誕生背景**：Java 1.0 就存在的元老
    
- **技術特徵**：屬於 Stream-oriented 且 阻塞式（Blocking）
當程式在讀取一個檔案或網路時，整條執行緒（Thread）會死死地卡在那裡等，直到資料讀完為止
    
- **常見類別**：`FileInputStream`、`FileOutputStream`、`BufferedReader`、`FileWriter`。
    

#### 2. NIO (`java.nio`) — 非阻塞式 I/O

- **誕生背景**：Java 1.4 引入。
    
- **技術特徵**：主打**非阻塞（Non-blocking IO）**
它不再使用傳統的串流（Stream）
而是改用 **通道（Channels）** 傳輸資料
並把資料裝在 **緩衝區（Buffers）** 中進行交換
大幅提升了高併發網路伺服器（如伺服器端連線）的效能
    

#### 3. NIO.2 (`java.nio.file`) — 全新檔案系統 API

- **誕生背景**：Java 1.7 引入（全面對 `java.nio` 進行大幅度補強）
    
- **技術特徵**：引進了更現代化、更符合操作系統原生行為的 **`Path`** 和 **`FileSystem`** 抽象概念，並提供了極其強大的工廠輔助類別 **`Files`**。
    
- **最大優勢**：它完美支援了現代**函數式程式設計（Functional Programming / Streams API）**。
    

### 舊的被淘汰了嗎？接下來要怎麼學？

**沒有！新舊功能並沒有互相完全取代。** 在許多情況下，它們只是「用不同的手段做同一件事」。在現實的企業專案中，你依然會看到舊系統在使用 `BufferedInputStream`
但同時，現代化的專案都在擁抱 NIO.2 帶來的函數式快感
