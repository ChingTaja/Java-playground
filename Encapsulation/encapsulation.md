1. 封裝的定義

- 在 Java 中，封裝的核心是**隱藏（Hiding）**
- 實作方式：使用 **`private`** 關鍵字，讓外部無法直接存取類別內部的成員

1. 為什麼需要封裝？ 有三個目的

- **簡化介面（Simplicity）：** 隱藏複雜的實作細節，使用者只需要知道如何使用（How to use），而不需要知道背後如何運作（How it works）
- **資料完整性（Data Integrity）：** 防止外部直接修改變數導致資料錯誤。例如：限制年齡不能被設為負數
- **解耦與靈活性（Decoupling & Flexibility）：** 讓「對外接口」與「內部邏輯」分離。就算內部程式碼或變數名稱改了，只要對外的 Method（介面）不變，就不會影響到其他使用該類別的程式

3. 關鍵術語

- **Getter Methods：** 封裝後用來取得私有資料的標準方法
- **Interface（介面）：** 在這裡並非指 `interface` 關鍵字，而是指 class **對外開放的操作管道**（例如 public 方法）

## Interface

當談到 **class's public** 或是 **published interface**
指那些**暴露在外、可供呼叫端程式碼存取**的類別成員

# 沒有使用封裝的風險

1. 機制失效（Bypassing Logic）： 類別內部寫好的邏輯（例如：`if (health > 100) health = 100;`）會被無視
   外部程式直接修改變數，讓你的防呆機制變成擺設
2. 資料污染（Data Corruption）： 因為繞過了檢查，資料可能會出現不合理的數值（例如：生命值變成 500，或變成負數）
3. 失去主導權（Loss of Control）： 類別不再能保證自己內部的狀態是正確的，因為任何人都可以從外部隨意動手腳
4. 安全性漏洞： 開放了不該開放的入口，增加程式出錯（Bug）或被惡意修改的風險
5. 增加程式碼的耦合度 : 外部程式碼直接依賴類別內部的變數名稱只要內部結構有一點點變動，所有用到該類別的地方都必須跟著修改，維護成本極高
6. 介面過於複雜且暴露細節： 對外部使用者來說，這個類別（API）變得很難用，因為他們必須了解內部的運作細節才能正確操作（使用者必須手動初始化所有欄位）

# 使用封裝的優勢

1. 內部的變動不會影響到外部的其他程式碼
2. 保護物件資料的存取 , 我們保護類別成員與某些方法不被外部直接存取
3. 防止規則被繞過 , 這能避免外部程式碼跳過我們在類別中建立的規則與限制
4. 確保資料有效性 , 確保新實例（Instance）在建立時，就已經初始化為有效的資料

# 封裝的原則

1. 建立建構子（Constructors）來初始化物件：這能強制要求只有具備『有效資料』的物件才會被建立
2. 對欄位使用 private（私有）存取修飾詞
3. 謹慎使用 Setter 方法 與 protected：只有在真的有需要時才提供
4. 只對外部程式碼需要使用的方法，開放非私有的存取權限
