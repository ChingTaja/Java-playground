# hashCode 的實作核心：為什麼使用質數？

在實作 hashCode 時，通常會選擇一個小質數（如 31, 29, 37, 43）作為乘數，原因如下：

- 均勻分佈：質數有助於讓雜湊值更均勻地散佈，減少不同物件產生相同雜湊值的機率（即減少 Hash Collision 雜湊碰撞）

- 處理規律性數據：當輸入資料具有特定模式或集聚性時，質數乘法能有效打破這些規律，優化分佈

- 為何避開極小質數？：像 2, 3, 5, 7 這些數字太小，容易被整除，會導致分佈效果不佳，進而影響雜湊集合的效能

註： 雖然 31 是常見標準（如 IntelliJ 預設），但某些非質數（如 33）在特定情況下也有不錯表現，唯質數仍是首選

# 如果打算將自定義類別（Class）放入雜湊集合中，必須遵循以下規則：

1. 同時覆寫：必須同時覆寫 equals() 與 hashCode() 兩個方法，這對維持資料正確性至關重要

# Java 雜湊集合實作類別
| 類型 | 介面    | 常見實作類別          | 特點                |
| -- | ----- | --------------- | ----------------- |
| 集合 | `Set` | `HashSet`       | 無序、不允許重複元素、查詢速度快  |
| 集合 | `Set` | `LinkedHashSet` | 保留插入順序、不允許重複元素    |
| 映射 | `Map` | `HashMap`       | Key 不可重複、無序、查詢速度快 |
| 映射 | `Map` | `LinkedHashMap` | 保留插入順序的 `Map`     |

遺留類別（Legacy）： Hashtable

注意： 現已有更高效的實作可取代，現代開發中通常不再建議使用
