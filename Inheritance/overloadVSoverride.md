# Method Overriding

物件導向程式設計（OOP）中實現「多型」的另一個核心機制
與重載不同，重寫是關於子類別如何「重新定義」父類別的行為

### 定義

- **前提**：必須存在於**父子類別（繼承）**關係中。
    
- **三同原則**：
    
    1. **名稱相同**
        
    2. **參數相同**（型別、數量、順序皆一致）
    
    3. **傳回類型相同**（或是其子類別，即共變傳回類型）
        

### 技術特性：執行時多型 (Runtime Polymorphism)

- **動態決定**：編譯器在編譯時只知道這是一個「父類別定義的方法」，但真正執行時，JVM 會檢查該物件的「真實型別」，如果是子類別物件，就執行子類別重寫的版本。
    
- **動態派送**：這讓程式碼更具彈性，你可以用父類別變數去操作不同子類別的物件，而得到不同的行為。
    

### `@Override` 註釋的作用

1. **安全性**：如果你不小心打錯字（例如將 `toString` 寫成 `tostring`），編譯器會報錯，告訴你「你並沒有重寫到任何方法」。
    
2. **可讀性**：讓其他開發者一眼看出這個方法是從父類別改寫而來的。
    

### 強制性限制 (The Rules)

- **不可重寫靜態方法**：`static` 方法屬於類別本身，不屬於物件實體，因此不支援多型的重寫。
    
- **存取權限**：子類別重寫的方法，存取權限**不能比父類別更嚴格**（例如：父類別是 `public`，子類別就不能是 `private`）。
    
- **final 方法**：如果父類別方法被標記為 `final`，則子類別完全禁止重寫它。

### Rule

#### 存取權限規則：只能放寬，不能收緊

這是為了確保「多型」的安全性。如果父類別承諾某個方法是公開的（public），子類別繼承後就不能把它藏起來（private）。

- **允許的順序（由嚴格到寬鬆）**： `private` < `(default)` < `protected` < `public`
    
- **範例**：
    
    - 父類別 `protected` → 子類別可為 `protected` 或 `public` (可以)
        
    - 父類別 `public` → 子類別設為 `private` (編譯錯誤)
        

####  禁止重寫的情況

並非所有繼承下來的東西都能改寫：

1. **Final Methods**：代表這是最終版本，不准子類別修改。
    
2. **Private Methods**：私有方法對子類別是隱形的，所以無法重寫（雖然可以在子類別寫同名方法，但那被視為一個全新的方法，而非重寫）。
    
3. **Constructors**：建構子不屬於繼承的一部分，因此不存在重寫問題。
   
4. - **不可重寫靜態方法**：`static nethod` 屬於類別本身，不屬於物件實體，因此不支援多型的重寫。只有 instance method 可以　overriden
   
5. 方法只能在子類別中被 overriden (沒有繼承，就沒有 overriden )
    

####  傳回類型：Covariant Return Types

這是一個較進階的觀念。子類別重寫時，回傳的東西可以比父類別定義的「更具體」

- **範例**：
    
    - 父類別方法回傳 `Animal`。
        
    - 子類別重寫該方法並回傳 `Dog` (這是合法的，因為 Dog 是 Animal)
      
####  `super` 關鍵字

當你想在子類別中**增強**父類別的功能，而不是完全**取代**它時，就會用到 `super`。

- **用法**：`super.eat();`
    
- **意義**：先執行父類別定義好的邏輯，接著再執行子類別特有的邏輯。


## Method Overloading

### 定義

- **名稱相同**：方法名必須完全一致。
    
- **參數不同**：這是關鍵！必須透過參數的**數量**、**類型**或**順序**來區分。
    
- **傳回類型**：可以相同也可以不同，但**不能**單靠傳回類型來區分兩個重載方法。
    

### 優點

1. **程式碼簡潔**：減少重複邏輯。
    
2. **降低記憶負擔**：開發者只需記住一個功能名稱（例如 `print()`），而不必記住 `printInt()`、`printString()` 等。
    

### 特性

- **類型支持**：靜態方法 (Static) 與 實體方法 (Instance) 都可以進行 overload
    
- **編譯時多型 (Compile-time Polymorphism)**：也稱為「靜態綁定」。編譯器在程式執行前，就已經根據傳入的參數決定好要執行哪一段程式碼。
    
- **發生位置**：
    
    - **通常**：在同一個類別 (Class) 中。
        
    - **進階**：也可以發生在父子類別之間（子類別繼承了父類別的方法名，並定義了不同的參數）


### Rule

如果兩個方法遵循以下規則
則會被視為 overload： 
1. 方法必須具有相同的名稱
2. 方法必須具有不同的參數
 
如果方法遵循上述規則： 
1. 它們可以具有相同或不同的傳回類型（Return types）
2. 它們可以具有相同或不同的存取修飾詞（Access modifiers，如 public, private）
3. 它們可以拋出相同或不同的受檢（Checked）或非受檢（Unchecked）異常（Exceptions）
