
1. 泛化 (Generalization) — 「由下而上」的歸納
泛化是把「具體的事物」變成的「通用的分類」
這是一個**找共通點（Commonality）**的過程。

行為： 你看到黃金獵犬、吉娃娃、拉不拉多，你發現它們都有四條腿、都會汪汪叫

結果： 你創建了一個更通用的類別叫做 Dog

關鍵字： 「Is-a」（是一個）

黃金獵犬 是一個 狗

狗 是一個 動物


2. 抽象化 (Abstraction) — 「由上而下」的契約（Contract）

- 定義: 抽象化是把複雜的細節隱藏起來，只留下必要的介面（Interface）
- 行為

當你定義 Animal 這個類型時：
```java
public interface Animal {
    void makeSound();
}
```
你決定：

所有動物都必須有 makeSound()
但不規定怎麼實作

👉 你建立了一個「契約（Contract）」

不在乎：
狗怎麼叫 🐶
貓怎麼叫 🐱
只保證：
只要是 Animal，就一定能發出聲音


定義：
 - 方法名稱
 - 參數
 - 回傳值
不包含：
 - 實作細節


# 抽象化 -> 像是契約

租車合約保證：

有方向盤
有煞車

 但不會寫：是油壓煞車還是電子煞車

➡️ 你只拿到「功能保證」，不關心實作

# 泛化 -> 像是分類
跑車 / 休旅車 / 卡車 

 在系統中都屬於「車輛」

# Concrete Method
擁有方法體（Method Body）
通常至少包含一條陳述句。這意味著它擁有實作碼
在正確的條件下會被執行
如果一個具體方法覆寫（Override）了一個抽象方法
我們就說這個具體方法『實作 (Implement)』了該抽象方法


- static：有時被稱為『類別方法』，與『實體方法』相對
它是直接透過類別呼叫的，不需要存取類別的任何特定實體
static 方法是屬於「類別」本身的
這意味著在 static 方法裡面，你不能直接使用 this 關鍵字
因為 static 方法執行時，可能根本還沒有任何物件實體存在

- final：被標記為 final 的方法不能被子類別覆寫

- default：這個修飾符僅適用於 interface

- native：這是另一種沒有方法體的宣告方式，但與 abstract 非常不同
它的方法體會由平台相關的程式碼實作
通常是用其他程式語言（如 C 語言）編寫的，並不常用。

- synchronized：此修飾符用於管理多個執行緒（Threads）如何存取該方法中的程式碼
