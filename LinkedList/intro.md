當一個基本型別的陣列被分配時，空間是**連續地（Contiguously）**分配給所有元素的

對於引用型別（Reference Types，即非基本型別，如 String 或任何物件），陣列元素存儲的不是數值本身，而是被引用物件或字串的地址

# ArrayList 的底層機制

- 實作方式：內部使用一個陣列來存儲物件的地址（References）
- 優點：查找速度極快
- 缺點（昂貴操作）：
  - 插入與刪除：在中間操作需要搬移大量元素（Shifting）
  - Reallocation：當容量不足，必須建立新陣列並複製舊資料，成本為

# Big O 表示法基礎

- n：代表資料量（元素個數）
- O(1) 常數時間：最理想狀態。無論資料量多大，耗時都一樣
  例如：透過索引存取 ArrayList 元素
- O(n) 線性時間：最常見的清單操作成本
  耗時與資料量成正比
  例如：在 ArrayList 的開頭插入元素（需要移動後面所有 n 個元素）

# ArrayList 的痛點：隨機插入/刪除的麻煩

像是一群人要住「連號房間」
但這時突然多了一個朋友要加入
106 號房已經有人住了
但為了讓所有人還是能住在一起
飯店只好叫你們全部退房，然後搬到另一層有 10 個連續空房的地方

# LinkedList 的切入點：

像是一場「大地遊戲」大家不需要住連續房間
e.g. 1 號房的人手裡有一張紙條，寫著：「2 號房在 5 樓」；2 號房的人手裡寫著：「3 號房在地下室」。
這張紙條就是**「指標（Pointer）」**

# constant Amortized Time:

雖然偶爾會有一次代價非常昂貴的操作，但因為這種情況極少發生，平攤到每一次操作後，平均成本依然非常低（常數級別）

為什麼這很重要？
如果你在開發一個對時間極度敏感的系統（例如：醫療監控儀器、高頻交易、賽車電子控制單元）
你就不能忽視那個「偶爾的 $O(n)$」
在這種情況下，ArrayList 的「均攤常數時間」可能就會變成風險

# 效能對比：ArrayList vs. LinkedList1.

1. 隨機存取元素 (Get / Set by Index)
   ArrayList: O(1) (常數時間)

原因：因為底層是連續陣列，Java 只要知道起始位址和索引值，就能透過簡單的數學公式直接跳到目標記憶體位置。

LinkedList: O(n) (線性時間)

原因：它沒有索引機制。如果要找第 500 個元素，必須從頭（Head）或從尾（Tail）開始，順著指標一個一個「數」過去。

2. 新增元素至末尾 (Add to End)
   ArrayList: O(1)
   ∗
   (均攤常數時間)

原因：大部分時候直接放進陣列空位即可。但當空間滿了，需要觸發一次 O(n) 的擴容（建立新陣列並拷貝舊資料）。平均下來速度依然極快。

LinkedList: O(1) (常數時間)

原因：它有指向尾部（Tail）的指標，只需建立新節點並把舊尾巴連上新節點即可，永遠不需要「搬家」。

3. 處理開頭元素 (Add / Remove from Front)
   ArrayList: O(n) (線性時間)

原因：這是在陣列最痛的操作。為了在索引 0 塞入新東西，後面所有的 n 個元素都必須往後「平移」一個位置。

LinkedList: O(1) (常數時間)

原因：只需修改頭部（Head）指標的指向即可，完全不影響後面的元素。

4. 中間插入與刪除 (Insert / Remove in Middle)
   ArrayList: O(n) (線性時間)

原因：雖然定位快，但插入後必須「平移」後半部的元素來填補或空出位置。

LinkedList: O(n) (線性時間)

原因：雖然「修改連結」本身很快（只需改兩張紙條），但你必須先花 O(n) 的時間「走到」中間那個位置。

💡 重點總結：如何決定用哪一個？
選 ArrayList 的時機：

資料主要是用來「讀取」和「存放」。

你大約知道資料量，可以在初始化時設定容量（Capacity）來消除擴容成本。

它是 Java 效能最好的通用型 List。

選 LinkedList 的時機：

你需要頻繁地在「開頭」做插入或刪除。

你打算把它當作「佇列（Queue）」或「堆疊（Stack）」來使用。

資料量極其龐大且極端不穩定，你不希望一次申請巨大的連續記憶體塊。

📖 名詞複習
O(1) (Constant)：效率最高，不論資料量 n 多大，時間都固定。

O(n) (Linear)：效率隨資料量 n 增加而等比例變慢。

O(1)
∗
(Amortized)：平均很快，但偶爾會因為特定機制（如擴容）而卡頓一下。

# LinkedList

一、底層架構：雙向鏈結串列 (Doubly Linked List)

## 結構特性

- 非索引架構
- 不像 ArrayList 使用「連續記憶體」
- 元素是分散的，透過「鏈結」串起來

## 節點 (Node) 組成

每個節點包含：

1. 資料本身 (data)
2. 指向前一個節點 (prev)
3. 指向下一個節點 (next)

## 端點概念

Head（頭）：起始節點
Tail（尾）：最後節點

## 雙端隊列（Deque）特性

可從「頭或尾」進行操作
支援：
從前新增 / 刪除
從後新增 / 刪除

二、效能分析（Big-O）
1. 搜尋與存取 → ❌ 慢（O(n)）
無法像 ArrayList 用 index 直接定位
必須「逐個遍歷」

e.g.
找第 5 個元素 → 要從 Head 或 Tail 一個一個走

2️⃣ 新增與刪除 → ✅ 快（O(1) / O(n)）
🔹 理想情況（已知位置）

e.g. O(1)

只需要：

斷開原本連結
建立新的連結

實際情況（位置在中間）
e.g O(n)

因為：
需要先「走到該位置」


## 為什麼比 ArrayList 快？
不需要搬移元素（No shifting）
不需要擴容（No resizing）


四、實務選擇
✅ 優先選 ArrayList（預設）

適用情境：

1. 讀取為主（Read-heavy）
2. 常用 index 存取
3. 資料量可預估

```java
new ArrayList<>(500_000);
```

✅ 使用 LinkedList 的情境

1. 頭尾操作頻繁
   addFirst()
   addLast()
   removeFirst()
   removeLast()
2. 大量插入 / 刪除
   不需要頻繁查 index
3. 資料量極大
   不想用連續記憶體

# ArrayList 和 LinkedList 優劣比較
👉 ArrayList：查詢快（Read） -> 存取快 ❌ 插入刪除慢（需搬移）
👉 LinkedList：修改快（Write） -> 插入刪除快（改指標）❌ 存取慢（需遍歷）
