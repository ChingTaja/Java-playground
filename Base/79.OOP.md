Object Oriented Programming

OOP有時也被稱為以類別為基礎的程式設計（class-based programming）

這種程式設計方式是從「類別」開始，類別會成為「物件的藍圖（blueprint）」

當你這麼做時，你會發現周遭有很多現實世界中的物件

例如，我現在坐在房間，我可以看到：
一台電腦、
一個鍵盤...

這些全部都是現實世界中物件的例子

現實世界的物件有兩個主要組成部分：

狀態（state） 與 行為（behavior）。

以電腦這個物件來說，它的狀態可能包含：
- 記憶體（RAM）的大小
- 使用的作業系統
- 硬碟容量
- 螢幕尺寸
這些都是用來描述該物件的特徵。

以電腦來說，行為可能包括：
- 開機
- 關機
- 發出聲音
- 在螢幕上繪製畫面
這些都可以被描述為電腦的行為

將現實世界的物件建模為軟體物件，是物件導向程式設計的核心基礎

軟體物件如何運作？

軟體物件會將它的狀態儲存在欄位（fields）中
這些欄位也可以稱為變數或屬性
而物件的行為則是透過**方法（methods）**來提供

那麼，**類別（class）**在這裡扮演什麼角色呢？

你可以把類別想成是用來建立物件的模板或藍圖。

類別會描述：

資料（欄位 fields）
行為（方法 methods）

這些合稱為類別成員（class members）
類別成員可以是欄位、方法，或其他相關元素

### static 與 instance 的概念

🔹 static 欄位
記憶體中只有一份
屬於「類別本身」

🔹 instance 欄位
每個物件都可以有不同的值
屬於「物件實例」
-----

如果一個欄位是 static，那麼在記憶體中只會有一份
並且這個值是**屬於類別本身的**

如果欄位不是 static，則稱為實例欄位（**instance field**）
每一個物件都可以有不同的值。

static 方法不能依賴任何單一物件的狀態，因此它不能存取實例成員。
換句話說，凡是需要操作**instance field**的方法，都必須是非 static 方法。


為什麼要用 class？

回想一下我們之前使用的基本資料型別（primitive data types），像是 int、short 等。
這些型別功能有限，只能做特定的事情

某種程度上，你可以把類別想成是一種「使用者自訂的強化資料型別」
雖然這不是完全正確的定義，但可以幫助你理解：

類別就像是「加強版的資料型別」

### Package 與存取權限

Java 用 package 來：

1.組織類別
2.避免命名衝突
3.控制存取範圍（最重要）

類別可以被 organizte 到稱為 package（套件） 的群組中
如果你沒有宣告 package，類別就會屬於預設套件（default package）

一個**頂層類別（top-level class）**只能有兩種存取修飾子：

1. public
2. 或完全不寫（package-private）

### access modifier

access modifier 用來控制其他程式可以如何存取這個類別

🔹 public: any others class in any package can access this class.

🔹 protected: protected allows classes in the same packagem and any subclasses in other packages, to have access to the member
允許「同一個 package」中的類別存取這個成員，
此外，它還允許「子類別（subclasses）」存取這個成員

🔹 private: no other class can access this member
一般來說，有一個重要原則：
**類別中的所有欄位（fields）都應該設為 private**
這跟類別本身不同，因為類別通常會使用 public

### 封裝（Encapsulation）

為什麼我們要把類別裡的所有欄位設為 private 呢？
這樣不是代表沒有人可以存取它們了嗎？

封裝有兩個重點：
1. 將 behavior 與 attribute 封裝在同一個物件中
2. 隱藏欄位（fields）與某些方法，不讓外部直接存取 (information hiding)

```java
public class Car {
    private String make;
    private String model;
    private String color;
    private int doors;
    private boolean convertible;

    // 和欄位不同的是，方法通常會設為 public
    //因為我們希望提供一個方式，讓使用者可以與物件進行互動
    public void describeCar() {
        System.out.println(doors + "-Door" + color + " " + make + " " + model + " " + (convertible ? "Convertible" : ""))
    }
}
```
