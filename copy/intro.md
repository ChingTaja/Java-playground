# Shallow vs. Deep Copies

陣列的淺拷貝意味著系統會建立一個全新的陣列結構，並配置相同數量的索引位置（Indexed Positions）

每一個索引位置，都會被指派與原陣列相同位置上完全相等的值

系統並不會針對被引用的元素（Referenced Element）另外複製出一份實例


- **防禦性複製（Defensive Copying）的雙向架構**
    
    - **Input（輸入端）**：將可變型別傳入不可變物件時，必須先建立防禦性複製副本，再指派給實例欄位
        
    - **Output（輸出端）**：當外部程式碼呼叫 Getter 檢索資料時，必須先複製一份副本再傳回給呼叫端
        
- **淺拷貝（Shallow Copy）與深拷貝（Deep Copy）的底層差異**
    
    - **淺拷貝**：僅複製資料結構本身（如配置相同長度的陣列新結構與索引位置），內部的元素依然直接指派原本的值
      這會導致新舊結構的引用（References）在記憶體中仍指向完全相同的一組物件實例。Java 內建的介面或 Helper 工具類別通常預設都是淺拷貝
        
    - **深拷貝**：不僅複製結構，連同結構內部的每一個元素物件都必須獨立 Clone 出全新的個體，這通常需要工程師手動實作（Manually Implemented）。
        
- **組合類別（Composite Classes）的多層巢狀（Nesting）地獄**
    
    - 類別的欄位如果包含其他類別的實例（如 Object 內包含 XYZ，XYZ 內又包含 JKL），若要達成絕對的不可變性（Immutability），僅針對第一層做深拷貝是不夠的。
        
    - 對於高度巢狀複雜的欄位結構，深拷貝必須透過遞迴（Recursively）的方式層層向下複製每一個內部欄位，否則最底層的資料引用（指針）依然會與原始物件共用，留下安全副作用



#### 唯讀視圖（View）與獨立複本（Copy）的決定性差異

| 比較       | List.copyOf(collection)             | Collections.unmodifiableList(list)  |
| ------------ | --------------------------------------- | --------------------------------------- |
| 機制       | 建立結構複本（Snapshot Copy）               | 建立唯讀視圖（Unmodifiable View）           |
| 與原始集合的關聯 | 與原始集合完全切斷關係。原始集合後續新增、刪除元素，不會影響到此複本| 僅是原集合的代理視窗。原始集合後續的任何異動，都會立即反應在該視圖上 |
| 設計目的     | 保護資料快照，不受原始集合後續增刪的影響    | 提供一扇可以觀察最新動態狀態、但限制客戶端（Client）直接修改的防禦視窗|
