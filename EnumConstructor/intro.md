- Enum 的底層真相（javap 的揭露）：
    
    - 使用 javap -p 反編譯會發現，enum 在底層其實是一個 `final class`，並且強制繼承自 `java.lang.Enum`
        
    - 你所寫的每一個列舉常數（如 BABY_BOOMER），本質上都是該類別中的一個 `public static final 欄位`
        
- 「一次性、全初始化」的建構子觸發機制：
    
    - 當你在 Main 類別中`第一次`存取 Enum 的任何一個成員（例如僅呼叫 Generation.BABY_BOOMER）時，Java 會一口氣初始化地圖上的`所有列舉常數`。因此，所有的建構子都會在第一時間被依序呼叫一遍，而不是只呼叫你點名的那一個
        
- 極度嚴格的 private 限制（無法 new）：
    
    - 列舉的建構子`強制且隱式為 private`。你不能在它的前面加上 public 或 protected。
        
    - 因為建構子是私有的，所以你在外部**絕對無法使用 new 關鍵字**來實例化任何新的 Enum 物件。它的實例數量在常數清單宣告完畢時就已經完全固定了
    - 因為外部無法 new，所以整個 Java 應用程式裡，Generation.BABY_BOOMER 在記憶體中**永遠只會存在那唯一的一個物件實例**。這保證了你可以安全地直接使用 == 來比較兩個列舉變數，而不用擔心它們會像一般 Object 一樣，因為 new 在不同記憶體位址而導致比對失敗
        
- 為常數附加屬性（自訂欄位與建構子）：
    
    - Enum 可以像一般類別一樣擁有實例欄位（如 startYear、endYear）。
        
    - 當你寫了自訂的帶參建構子後，隱式的無參數建構子就會消失。此時常數宣告的後方必須用圓括號 (傳入值) 來呼叫對應的建構子。實例欄位強烈建議加上 final。
        
- 高級語法：常數的「類別主體（Class Body）」
    
    - 如果某個特定的列舉常數（如 GEN_Z）需要特殊的行為，可以在它後面加上大括號 { ... } 來編寫專屬於它的類別主體。
        
    - 如果想在裡面執行列印等動作，無法直接撰寫陳述式，必須像程式碼中那樣包裹在雙重大括號中，形成「實例初始化區塊（Instance Initializer）」方能成功編譯
